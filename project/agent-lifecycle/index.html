Scaled Cognition: Agent Lifecycle

Scaled Cognition’s Agent Builder lets teams build, simulate, defend and evaluate customer-experience agents on its APT-1 model. I designed the end-to-end lifecycle, from a one-line description to a tested agent running in production.

The Challenge

Shipping a reliable support agent takes far more than a prompt. Teams have to write the rules it follows, connect it to real systems, test it against realistic conversations, guard it against misuse and prove it performs before customers ever see it.

Each of these steps needs different expertise, and mistakes found late are expensive. The challenge was to make the whole lifecycle feel like one guided flow, so a team always knows what is done, what is next and whether the agent is ready.

A persistent stepper carries every agent from definition to deployment. A live chat panel stays open beside each step, so every change can be tried in a real conversation the moment it is made.

Agent Lifecycle

Every agent at a glance: how many are deployed, the average pass rate and conversations this week. Each card shows its status, pass rate, conversations, guardrails and build progress, so teams can see which agents are live, in evaluation or still in draft.

Building starts with a plain-language description of what the agent does. APT-1 can improve the wording, and templates for banking, telecom and insurance give teams a head start. The live chat is ready from the first step.

Rules are grouped by topic and switched on or off individually, and each one is marked if it is checked during evaluation. APT-1 suggests missing rules it found in simulated conversations, shown in a dashed card to accept or dismiss.

Functions and data types are generated from example JSON and laid out as a graph, showing which function returns which type. APT-1 flags missing functions, such as cancel_reservation, with a short reason, and the library on the left keeps every type one click away.

GenAPI simulates every function, so the agent can be tested without touching real systems. Teams set general behaviour, such as realistic names and prices, plus specific scenarios like a fully refundable order. APT-1 suggests edge cases worth covering, such as a payment failure on 5% of refunds.

The live chat makes the agent’s reasoning visible. As a customer asks to cancel an order, each function call appears inline with its arguments and mocked response, followed by a progress list of what the agent is doing, so builders can see exactly why it answered the way it did.

Agent Defender protects the agent from misuse. Four core protections, from blocking adversarial inputs to securing tool access, sit next to custom rules such as sending refunds over $500 to a human. A red alert in the live chat shows a prompt-injection attempt being blocked and logged in real time.

An evaluation runs in three visible stages: test cases generated from the agent spec, large-scale simulation with virtual customers, and a scorecard. The history on the left shows every run with its pass rate, and the scorecard on the right summarises conversations, turns, tokens and prompts.

Any test case can be opened to replay the full conversation, with each agent turn, virtual-customer message and GenAPI call in order. The right panel shows the scenario’s instructions, context and expected results, so a failure can be traced to the exact step that went wrong.

Before going live, a readiness checklist confirms every step and flags anything below threshold, here 2 test cases under 70%. Teams pick staging or production, and the generated agent.yaml shows the full configuration as code.

Deployment ends with a clear next step. The confirmation names the version that is live on staging, suggests monitoring conversations first, and offers a single button to promote the agent to production when the team is ready.

The Result

Seven steps, one consistent layout: a stepper on top, the work in the centre and the live chat on the right. Teams always know where they are, what is left, and can test any change the moment they make it.

APT-1 acts as a co-pilot throughout, suggesting rules, functions, scenarios and guardrails that builders can accept or dismiss. Every agent reaches deployment with a scorecard, a readiness checklist and its full configuration as code.
